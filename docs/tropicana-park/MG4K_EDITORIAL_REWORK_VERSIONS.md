## Решение и зачем оно нужно

При визуальном дефекте мастер **не утверждается**, а получает неизменяемое решение `REWORK_REQUESTED` с классифицированными замечаниями, текстом, датой и SHA-256. Скачивание, передача в MG4K и художественная генерация для отклонённой версии запрещены. Новая версия получает отдельный UUID, собственные исходник, Tech Master и QA. Материалы V1 остаются в R2 и никогда не заменяются V2.

**Существенное ограничение:** детерминированный технический процессор сохраняет геометрию без HDR, но не исправляет автоматически произвольные оптические и перспективные дефекты. Поэтому новый цикл **не генерирует «исправленную» V2 из той же самой фотографии**; для V2 требуется действительно откорректированный исходник, прошедший человеко-контролируемый Perspective Lock. Без нового изображения система не будет изображать результат коррекции.

## Статусы и действия

| Состояние | Разрешённое действие |
| --- | --- |
| `AWAITING_HUMAN_QA` | Утвердить либо «Вернуть на доработку» |
| `REWORK_REQUESTED` | Просмотреть обязательные замечания, загрузить исправленный исходник |
| `REVISION_CREATED` | Открыть новую версию по сохранённому ID |
| `AWAITING_TECH_PROCESSING`, `PROCESSING` | Только реальный прогресс технической обработки |
| `AWAITING_HUMAN_QA` (V2+) | Сравнение оригинал / предшествующий Tech Master / текущий Tech Master |
| `TECH_MASTER_APPROVED` | Скачать утверждённый TIFF; передать в MG4K с локерами |

## Контракт данных

- `technical/decision.json` неизменяемый: `decision=REWORK_REQUESTED`, `categories`, `note` (12–2000 символов), `master_sha256`, `at`, `owner_session_id`, `revision_num`.
- Категории: `geometry`, `exposure`, `color`, `detail`, `materials`, `other` (не менее одной).
- `rework/revision.json` в папке родителя: `job_id`, `revision_num`, `source_sha256`, `parent_master_sha256`, `rework_decision_at`.
- `job.json` новой версии: `parent_job_id`, `root_job_id`, `revision_num`, уникальный UUID и новый SHA.
- Все технические файлы V1 остаются по своему ID, V2 сохраняется отдельно; V3 повторяет тот же механизм.
- Допустимы JPG, PNG, WEBP до 8 МБ; совпадение SHA с предыдущим исходником отклоняется.
- Доступ сохраняется через прежнюю авторизованную сессию или криптографический доступ к семейной цепочке версий (сервер хранит только хэш).
- API: `POST /api/editorial/job/decision` с `REWORK_REQUESTED`, `POST /api/editorial/job/revision`, `GET /api/editorial/job/source`, `GET /api/editorial/job/status`, `GET /api/editorial/job/preview`.

## Безопасность

1. **Нет автоматического утверждения QA.** Реальный человек должен визуально подтвердить финальную версию.
2. **Нет платной генерации.** Для новой версии запускается только бесплатный технический Cloudflare Workflow.
3. **Нет перезаписи истории.** Решение QA в V1 необратимо, хэш-история сохраняется, не используется перезапись V9/V10/Editorial 01.
4. **Нет фальшивой коррекции.** Источник должен реально отличаться; геометрию и архитектуру проверяет ответственный.
5. **Fail-closed:** попытки скачивания или передачи неутверждённой версии возвращают HTTP 409; чужие сессии — 404.
6. **QA-сравнение** — исходник, Tech Master предыдущей версии, Tech Master новой версии в полном разрешении.

## Приёмка и оставшийся риск

Проверки кода: категории и текст замечаний, невозможность изменить QA-решение, отдельный UUID и SHA V2, право доступа к source и статусу, отказ от повторной неизменённой версии, отсутствие автоматической передачи в MG4K, допуск утверждения и передачи только после независимого QA V2.

**За пределами текущего изменения:** автоматический интеллектуальный редактор геометрии (Perspective Lock), очередь художника с назначением исполнителя, универсальные RAW/ARW-проявщики, сравнение архитектурных контрольных точек. Их нельзя обозначать как готовые после публикации одного лишь версионного контура.

Текущий производственный пример — реальное фото 2561×1287, TIFF 19,78 МБ, технический QA PASS, ожидает решения пользователя. Старые исходники и технические мастера остаются в R2.

## Что осталось для 100%

1. Пользователь открывает ранее загруженный снимок, выбирает «Вернуть на доработку» и указывает конкретные замечания.
2. Исполнитель геометрически исправляет source в соответствии с Perspective Lock (без художественной генерации и HDR) и загружает изменённую фотографию.
3. Проверка V2 в браузере по сравнению с исходником и V1, утверждение, загрузка TIFF, передача в MG4K.
4. Нужна независимая автоматизация **контролируемой** коррекции геометрии, если предполагается создавать V2 совсем без участия графического редактора. Пока автоматических исправлений перспективы **нет**, это не скрыто.

**Финальное правило:** QA является формальным переходом; без человеческого APPROVED текущая версия не выпускается и не расходует генеративные кредиты.
