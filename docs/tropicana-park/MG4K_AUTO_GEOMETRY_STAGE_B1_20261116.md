# MG 4K / «Тропикана-парк» — AUTO PERSPECTIVE LOCK, этап B1

**Дата:** 16.11.2026  
**Целевое действие:** автоматический анализ архитектурных направляющих и измерение геометрии без ручных четырёх точек.  
**Этап реализации:** B1 — автоматический анализ сцены / геометрические наблюдения.  
**Фактический статус:** реализовано и объединено с main. Продуктовый автокорректор перспективы **ещё не реализован**.  
**Прогресс полного конвейера:** прежняя управленческая оценка ~70%, не пересчитывать по коммитам или CI.

## Реализовано

- `scripts/editorial_auto_perspective_analysis.py`: OpenCV Line Segment Detector определяет архитектурные прямые; вычисляет группы вертикалей, горизонтальных направляющих, наклон вертикальных линий, согласованность направлений (взвешенная медиана и MAD), достаточность распределения линий по площади кадра.
- Кандидаты точек схода рассчитываются через пересечения независимых горизонтальных прямых; система явно различает `CANDIDATE`, `UNSTABLE`, `PARALLEL_OR_UNSTABLE` и `INSUFFICIENT_LINES`.
- Консервативная оценка замысла: `FRONT_CANDIDATE` / `ANGLE` / `UNKNOWN`. Профиль для художественных/ночных сцен ещё не калиброван; не объявлять `EDITORIAL` автоматически без независимой классификации.
- `scripts/editorial_raster_technical_master.py` запускает анализ на оригинальных пикселях **до любой обработки** и сохраняет `auto_geometry_analysis` и `auto_geometry_analysis_status` в `technical/qa.json`.
- Строго разделены `AUTO_GEOMETRY_ANALYZED` и `AUTO_GEOMETRY_CORRECTED`. Последний сейчас равен `NOT_APPLICABLE`: анализа недостаточно для отметки «перспектива исправлена».
- При недостаточных независимых линиях система возвращает `HOLD` для вертикального преобразования; старый технический мастер, SHA, запрет HDR, human QA и архитектурные HARD-локеры не меняются.

## Инженерные гейты

`tests/editorial-auto-scene-geometry.py`:
1. Пустая однородная сцена без прямых → `HOLD`, `intent=UNKNOWN`, нет выдуманных углов.
2. Прямой синтетический фасад → обнаружение линий, малая оценка завала, отсутствие ложной «исправленной» версии.
3. Синтетический фасад с реальным наклоном камеры → обнаружение наклона и расчет кандидата компенсации, без автоматического изменения пикселей.
4. Полная цепочка PNG → фактический TIFF16 → QA JSON → сохранение SHA/исходных пикселей без HDR/генерации.

## Почему это ещё не полная AUTO-коррекция

Необходимо реализовать и независимо подтвердить:
- камерную геометрическую модель и калиброванный confidence; выбор `FRONT/ANGLE/EDITORIAL` по реальным сценам;
- безопасное автоматическое устранение завала вертикалей/roll/pitch без повреждения соседних плоскостей и без обрезки важных объектов;
- определение охранных зон здания, людей и композиционно ценных областей и автоматическое кадрирование;
- профили объектива, корректный RAW processing, экспозицию и WB с учетом ночной сцены;
- автоматический выпуск действительно изменённого TIFF с доказательствами residual before/after и human QA.

**Запрет:** до прохождения этих гейтов алгоритм не должен самостоятельно выпрямлять архитектурную перспективу, подставлять четыре точки или выдавать конвертацию PNG→TIFF за исправление.

**Состояние исходного пользовательского задания:** перед новым выпуском не инициировались утверждение, отклонение, повторная обработка или замена источника. Новая модель анализа применяется при создании новых технических мастеров после обновления контейнера; старый QA-протокол нельзя задним числом считать прошедшим Auto Perspective.

**Следующее конкретное действие:** B2 — отладить кандидатов на наборе эталонных архитектурных фотографий и реализовать автоматическое безопасное исправление roll/вертикалей с программным сравнением и неизменным оригиналом.
